# 情侣加热

> 「爱你的老婆冬天就要用暖宝宝」×「弹幕人生」融合版，当前 **1.5.8 稳定版**（versionCode 18）。
> 包名仍是 `io.github.wumisc.hotwinter`，**直接覆盖升级**，不用卸载；应用名与磁贴名都改成了「情侣加热」。

一个靠 CPU 恒温发热给手取暖、同时能和对象互发弹幕的 Android 小工具。
不是烤手机，是用可控占空比把机身温度稳在目标值；弹幕走局域网/蓝牙，不依赖云端。

- minSdk 26 / targetSdk 37 / compileSdk 37，纯 Java + AppCompat，无 Compose
- 深色模式：`Theme.AppCompat.DayNight.NoActionBar` + `values-night/colors.xml`，跟随系统
- 许可：AGPL-3.0

## 1.5.8 稳定版改了什么

- 首页刷新、页面切换、频道创建/加入/扫码全部加了空值和初始化门闩，布局异常不再直接闪退
- 主线程刷新连续失败 5 次会自动停表，不会把 ANR 拖成崩溃
- 发热/情侣/悬浮弹幕三个前台服务补齐启动失败回滚，通知被限制时不再硬崩
- 情侣服务只用一个 Handler 管自动释放，连续发命令不会被旧回调误停
- 弹幕与蓝牙监听器逐个隔离，单个回调异常不影响其他监听
- 雪山/火山、温度球和弹幕滚动从 60fps 降到约 30fps，长时间发热更省电
- 新增启动/切页/刷新/捐赠入口的 UI 冒烟测试，当前 34 个 JVM 测试全过

## 它是怎么热的

24 ms 一个切片，按当前占空比跑浮点负载，剩余时间 park；线程优先级压到后台，
线程数 = `round(核心数 × 占比)` 并夹在 `[1, 核心数-1]`，永远给系统留至少一个核。

每 2.5 秒一次温控决策：

1. 硬保护：电量 ≤ 保护线且未充电 → 停；系统热状态 ≥ SEVERE 或电池温 ≥ 45°C → 停
2. 降档：MODERATE → 上限 0.35；电池 ≥ 42°C → 上限 0.25；省电模式 → 上限 ×0.7 且目标 −1.5°C
3. PI 调节：`duty = cap × 0.45 + 0.09 × 误差 + 0.006 × 积分`，下限 0.12，单次变化 ≤ 0.15

温度到目标后占空比自动往下掉，掉到刚好维持目标——省电从这里来。
档位热预算：温和 1.6W / 标准 3.2W / 强力 5.0W / 极热 7.2W。

SoC 自适应：先认芯片（`Build.SOC_MODEL`、`ro.soc.model`、`ro.board.platform`、`Build.HARDWARE`、`/proc/cpuinfo`），
按「可持续热功率 / 单线程功耗 / 线程上限」分配线程，认不出就走保守方案，不搞一棒子全核拉满。

## 弹幕模块（融合自「弹幕人生」）

保留原应用的设置项与通信方式，并新增蓝牙通道：

- **设置**：昵称、房间/频道、字号（10–30）、飞行速度（0.5–2.0x）、文字透明度（35–100%）、车道数（2–12）、显示昵称
- **通信 1：局域网 UDP 广播**，默认端口 `47821`，同房间才互相看得见，不需要服务器
- **通信 2：蓝牙 RFCOMM**，和情侣模式共用一条链路（UUID `6f2a9d4e-1c3b-4a77-9e21-8b0f5d3c7a10`），
  已配对并连上后，弹幕和「为她加热 / 停止加热」都走这条链路
- **悬浮弹幕**：全屏透明、不吃触摸，屏幕上方 42% 区域按车道从右往左滚；需要悬浮窗权限
- **发送**：开了 UDP 就广播、连了蓝牙就发蓝牙，两边都可用时同时发；本机始终先显示一份
- **协议**：`DM\t房间\t昵称\t消息id\tBase64(正文)`；正文上限 200 字，坏包/异包直接丢弃，旧四段包兼容
- **隐私边界**：UDP 是局域网广播，同网段同房间的人理论上都能收到，别发隐私；蓝牙链路只接受已配对设备

### 局域网收不到怎么排查

1. **Android 17 及以上**：首次打开局域网开关会弹「本地网络 / 附近的设备」授权，必须允许；拒绝后 UDP 会被系统网络栈直接拦掉（EPERM）。去系统设置 → 应用 → 情侣加热 → 权限 → 附近的设备 里补授权。
2. 两台手机连同一个 Wi-Fi，**房间名和端口完全一致**；改完输入框直接点发送也会自动保存，不需要先点别处。
3. 路由器开了「AP 隔离 / 访客网络」时广播过不去：在弹幕页填对方的 **Wi-Fi IP**（状态栏会显示本机 IP，如 `192.168.1.5`），走单播直发。
4. 状态栏应显示「局域网监听中 · 端口 47821 · 本机 192.168.x.x」；只显示「未开启」说明 socket 没起来，多半是端口被占。
5. 关掉悬浮弹幕不会停掉局域网开关；局域网的生命周期只跟那个开关走。

没有复刻原版的公共 MQTT 中继——那属于外部公共服务，本版只保留你点名的局域网与蓝牙。
需要异地互发时可以后续再加自建中继，不会默认把内容发到公共节点。

## 界面

底部圆角悬浮导航栏，四页：

- **首页**：实景雪山/火山双态背景（透明山体，静态氛围层，不逐帧刷屏）、大字温度、开始/停止、四档强度、目标温度、省电与保护、实时状态
- **功能**：系统适配、通知保后台、日志开关、情侣模式（配对 / 为她加热 / 停止）、设备检测
- **弹幕**：悬浮开关、发送框、最近弹幕、弹幕样式、局域网 UDP、蓝牙链路
- **关于**：版本与包名、捐赠支持、功能建议、开源主页、感谢名单、许可

状态栏与手势条都由 `WindowInsets` 避让；页面底部预留 108dp，导航栏不会压住内容。
控制中心磁贴「情侣加热」：点一下开始，再点一下停止。

## 闪退了怎么查

应用内置了兜底崩溃记录：闪退后重新打开，进「功能 → 运行诊断」，能看到上次崩溃的时间、机型、系统版本和完整堆栈，点「复制崩溃信息」可以直接发出来。
日志同时写到 `/storage/emulated/0/Android/NBB/crash.log`（能写时）和应用私有目录，最多保留 256KB。

## 通知与日志

- 通知标题统一「爱情加热中」；开「通知保后台」后停止加热也保留待机前台通知，降低被系统回收的概率
- 日志开关默认关闭；打开后写 `/storage/emulated/0/Android/NBB/hotwinter.log`，512KB 滚动到 `hotwinter.old.log`
- 捐赠支持：支付宝 / 微信收款码内置在应用里，点「关于 → 捐赠支持」直接弹出双码，不需要放文件，也不需要存储权限
- 隐私说明：开源仓库中的两张收款码已替换为占位图，避免公开个人收款账户；自行构建时替换 `drawable-nodpi/` 下的同名文件即可

## 构建

```bash
export JAVA_HOME=/path/to/jdk21
gradle :app:testDebugUnitTest
gradle :app:assembleDebug
gradle :app:assembleRelease   # 读 keystore.properties
```

需要 **Gradle 9.9.1 + JDK 21 + Android SDK 37**；仓库没有附带 wrapper，用本机 Gradle 即可。

`keystore.properties` 与 `keystore/` 不进仓库；升级必须用同一个 keystore，否则要卸载重装。
源码仓库同样不包含 `local.properties` 和构建产物，首次构建请用 Android Studio 或命令行指向本机 SDK。

## 安全边界

电池温度是唯一硬指标：45°C 硬停、42°C 压到 0.25、系统热状态 SEVERE 直接停，写死不接受设置影响。
`/sys/class/thermal` 只做展示，不参与安全判定。
冬天室外尽量把手机放口袋里，风直吹会抵消大部分热量。
